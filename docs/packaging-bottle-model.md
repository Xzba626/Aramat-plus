# Packaging / Bottle Model — обязательная спецификация

**Проект:** ARAMAT PLUS  
**Статус:** Утверждённый ориентир (не реализовано в коде)  
**Связь:** [Vision](vision.md) · [Architecture](architecture.md) · [Product Nomenclature](TZ-PRODUCT-NOMENCLATURE.md)

---

## Главная идея

**Флакон — расходный материал упаковки, а не товар.**

| Флакон | Товар (Product) |
|--------|-----------------|
| Не продаётся отдельно | Продаётся в POS |
| Нет выручки | Есть `salePrice` |
| Не в каталоге POS | В каталоге POS (store stock) |
| Не создаёт прибыль как SKU | Участвует в выручке |
| Влияет только на COGS | Liquid + packaging = COGS |

---

## Запрещено (жёстко)

Не создавать отдельные товары вида:

- `Dior Sauvage 5ml`
- `Dior Sauvage 10ml`
- `Dior Sauvage 50ml`

**Почему:** ломаются аналитика ароматов, остатки, FIFO, история продаж, валовая прибыль.

Не учитывать флакон как **Expense** (аренда, ЗП, коммунальные).  
Флакон входит в **COGS** конкретной продажи разливного аромата.

---

## Сущности (целевая модель)

### Product (жидкость)

Пример: **Dior Sauvage**

- `accountingType`: `WEIGHT`
- Остаток: мл (склад / магазин через `StockBalance` + `Batch`)
- `salePrice`: цена за мл (или за единицу разлива — одна строка в чеке)
- FIFO на партиях жидкости

### PackagingMaterial (упаковка)

Пример: **Флакон 10 мл**

- Собственный справочник (не `Product`)
- Поля: `sizeMl`, закупочная стоимость, остаток (шт), FIFO-партии
- Склад упаковки: центральный + transfer в магазин (как у товара)
- **Нет** `salePrice`, **нет** POS-каталога, **нет** строки выручки

### Sale (одна транзакция)

При продаже `10 мл Dior Sauvage` + флакон `10 мл`:

1. **Liquid:** `Product` WEIGHT → −10 мл → FIFO  
2. **Packaging:** `PackagingMaterial` → −1 шт → FIFO  

**COGS продажи** = стоимость жидкости + стоимость флакона.

Пример:

| Компонент | Расчёт | Сумма |
|-----------|--------|-------|
| Духи | 10 мл × 2 сом/мл | 20.00 |
| Флакон 10 мл | 1 × 0.80 | 0.80 |
| **COGS** | | **20.80** |
| Выручка | | 40.00 |
| **Валовая прибыль** | | **19.20** |

В `SaleItem` — только жидкость (выручка).  
Упаковка — отдельная связь `SalePackagingUsage` (или аналог) с frozen `costPerUnit`.

## POS: сценарий WEIGHT (обязательный)

```
Выбор аромата → Ввод мл → Выбор доступного флакона → Проверка наличия → Продажа
```

1. Продавец выбирает аромат (WEIGHT, store stock).
2. Вводит количество в **мл** (не только +1 шт).
3. Система предлагает флаконы: 5 / 10 / 30 / 50 мл / свой объём.
4. Если выбранного флакона **нет на остатке магазина** — продажа **блокируется**.
5. Одна транзакция списывает жидкость + флакон.

## Аналитика владельца

Раздел **«Расход упаковки»** (не в выручке):

- Продано мл духов (по магазину / сети)
- Использовано флаконов по размерам (шт)
- Стоимость упаковки (COGS packaging)
- Периоды: сегодня / неделя / месяц / год

Флакон **не** попадает в:

- Выручку
- «Продажи товаров» как отдельный SKU
- Прибыль как отдельный товар

Флакон **попадает** в:

- COGS
- Себестоимость продажи
- Аналитику использования упаковки

## Seller isolation (архитектура остатков)

Цепочка обязательна:

```
Warehouse stock → Transfer → Store stock → Seller POS (только свой магазин)
```

Продавец **никогда** не видит:

- складские остатки;
- остатки другого магазина.

Smoke: `npm run test:seller-isolation`
