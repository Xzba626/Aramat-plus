# UI Design System №4

**Проект:** ARAMAT PLUS ERP  
**Версия:** 1.0  
**Статус:** Единый источник визуальных правил для всего интерфейса  
**Связанные документы:** [Vision](vision.md) · [UX Specification](ux-specification.md) · [UI Blueprint №13](ui-blueprint.md) · [Frontend Architecture №11](frontend-architecture.md) · [Design tokens (кратко)](design-system.md)

---

## 1. Цель документа

Документ определяет единый визуальный стиль системы.

Все экраны, кнопки, формы, таблицы, карточки, уведомления и другие элементы интерфейса должны использовать этот Design System.

Главная задача — современная ERP, в которой сотрудники работают весь день без усталости глаз, а владелец быстро находит нужную информацию.

---

## 2. Философия дизайна

Интерфейс должен создавать ощущение:

- профессиональной корпоративной системы;
- высокой скорости работы;
- порядка и надёжности;
- современного продукта.

**Это не интернет-магазин.** Это рабочий инструмент для ежедневного использования.

---

## 3. Основные принципы

Каждый экран соответствует правилам:

- минимализм;
- отсутствие визуального шума;
- одинаковое расположение элементов;
- единая система цветов;
- единая система отступов;
- одинаковые размеры компонентов;
- переиспользуемые UI-компоненты (не «уникальный» стиль на каждом экране).

---

## 4. Две поверхности интерфейса (ключевое решение)

Внутри одного продукта — **две согласованные, но независимые поверхности**. Общие токены бренда и компоненты, разная плотность и навигация.

### 4.1 Owner Console (владелец / менеджер)

| Параметр | Решение |
|----------|---------|
| Устройство | Desktop-first, mobile полноценный |
| Навигация desktop | Тёмный левый sidebar 260px |
| Навигация mobile | Drawer + нижняя навигация для ключевых разделов |
| Контент | Светлый фон, широкие таблицы, графики, аналитика |
| Плотность | Средняя / высокая (много данных) |
| Доступ к данным | Полный (по роли), включая себестоимость и финансы |

### 4.2 Seller POS (продавец)

| Параметр | Решение |
|----------|---------|
| Устройство | **Smartphone-only** (основной сценарий) |
| Навигация | **Bottom Navigation** (работа одной рукой) |
| Контент | Крупные кнопки, минимум экранов, продажа на одном flow |
| Плотность | Низкая (крупные тач-цели ≥44px) |
| Доступ к данным | Только продажа, корзина, история, остатки своего магазина — **без себестоимости и аналитики** |

### 4.3 Warehouse Console (кладовщик)

Базируется на Owner Console (светлый контент + sidebar / compact nav), но меню ограничено складом (см. UX Spec §3).

Seller может использовать:

- или компактную тёмную тему POS (`theme-dark`) для снижения бликов в магазине — по настройке профиля.

В обеих темах **фирменный красный** остаётся цветом primary CTA («Продать»).

## 6. Цветовая логика данных

| Цвет | Смысл |
|------|--------|
| **Зелёный** | прибыль, успешная операция, подтверждено, оплачено |
| **Красный (danger)** | расход (−), возврат, ошибка, удаление, критический остаток |
| **Жёлтый / оранжевый** | ожидает подтверждения, запрос скидки/возврата, низкий остаток |
| **Синий** | информационные и системные сообщения |
| **Фирменный красный** | ключевые действия бренда (Создать, Сохранить, Продать, Отправить) |

Правило: пользователь должен понимать смысл числа **по цвету**, не читая подпись.

---

## 7. Типографика

Один современный UI-шрифт на всю систему: **Geist Sans** (или системный fallback).

| Уровень | Размер (desktop) | Вес | Использование |
|---------|------------------|-----|----------------|
| Page title | 24px | 700 | Заголовок страницы |
| Section title | 13px uppercase / tracking | 700 | Метки секций |
| Card title | 16–18px | 700 | Заголовок карточки |
| Body | 15px | 400–500 | Основной текст |
| Secondary | 13–14px | 400 | Второстепенный |
| Caption | 11–12px | 500–600 | Подписи, meta |
| Table | 14px | 400–600 | Ячейки |
| Metric | 28px | 700 | KPI на dashboard |

Seller (mobile): базовый текст ≥15px, primary button ≥16px / bold.

Во всей системе — одинаковые размеры и межстрочные интервалы.

---

## 8. Сетка и отступы

Базовая единица: **4px**. Рабочий шаг: **8 / 12 / 16 / 24 / 32**.

| Контекст | Отступ |
|----------|--------|
| Page padding desktop | 24–32px |
| Page padding mobile | 16px |
| Gap между карточками | 16–24px |
| Card padding | 20–24px |
| Form field gap | 12–16px |
| Sidebar width | 260px |

Все карточки, формы и таблицы выравниваются по одной сетке.  
Owner content max-width: ~1400px по центру рабочей области.

## 9. Кнопки

### Primary (фирменный красный)

Главные действия: **Продать · Сохранить · Создать · Отправить · Войти**.

### Secondary (нейтральная)

**Отмена · Назад · Закрыть · Вторичные действия.**

### Soft

Фон `--brand-soft`, текст `--brand` — быстрые действия на dashboard.

### Danger

**Удалить · Списать · Архивировать** — всегда с модальным подтверждением.

### Размеры

| Size | Высота (min) | Где |
|------|--------------|-----|
| sm | 36px | Таблицы, компактные панели |
| md | 40–44px | Формы Owner |
| lg | 48–52px | Seller CTA «Продать» |

Скругление: `--radius-control` (12px).  
Состояния: default / hover / active / disabled / loading.

---

## 10. Поля ввода

Единый стиль для всех типов:

- текст, число, дата, время, пароль;
- поиск;
- select / combobox;
- загрузка фотографии.

Правила:

- высота контроля согласована с кнопками md;
- focus: border brand + ring `--brand-ring`;
- ошибка: border danger + текст ошибки **под полем**;
- label над полем, не placeholder вместо label.

Компоненты: `Input`, `Search`, `Select`, `Textarea`, `DatePicker`, `FileUpload`.

---

## 11. Таблицы (Owner)

Единая структура:

- sticky header;
- сортировка;
- фильтрация и поиск;
- пагинация;
- экспорт (CSV / Excel — по этапу);
- пустое состояние с CTA.

На mobile таблицы → **карточки** с раскрытием деталей (см. UX Spec §16).

Seller почти не использует таблицы — списки и карточки товаров.

---

## 12. Карточки

Используются для: товара, магазина, пользователя, бренда, KPI, быстрых действий.

Структура карточки:

1. Заголовок  
2. Основные данные  
3. Быстрые действия (опционально)  
4. Переход к подробной информации  

Параметры: radius 18px, border `--border`, shadow `--shadow-card`, hover лёгкий lift для интерактивных.

---

Единый набор (Lucide / единый SVG-набор). Не смешивать стили emoji в production Owner Console — emoji допустимы только как временные placeholders.

| Смысл | Иконка |
|-------|--------|
| Главная | Home |
| Склад | Warehouse / Package |
| Магазины | Store |
| Продажа / Корзина | ShoppingCart |
| Пользователи | Users / User |
| Уведомления | Bell |

| Настройки | Settings |
| Аналитика | Chart |
| Возврат | Undo2 |
| Перемещение | ArrowLeftRight |

Размер в sidebar: 20px. В bottom nav Seller: 22–24px.

## 14. Адаптация и навигация

### Компьютер (Owner)

- Полная боковая навигация (тёмный sidebar).
- Широкие таблицы, несколько колонок.

### Планшет

- Компактная боковая панель / drawer.
- Уменьшенные таблицы, 2 колонки KPI.

### Телефон — Seller (обязательно)

**Bottom Navigation:**

```
🏠 Главная
🛒 Продажа
🧺 Корзина
🔔 Уведомления
👤 Профиль
```

Быстрое переключение одной рукой. Корзина показывает badge с количеством позиций.

### Телефон — Owner

- Нижняя навигация для ключевых разделов (Главная, Склад, Магазины, Уведомления, Ещё).
- Пункт «Ещё» / hamburger → полное боковое меню (Аналитика, Настройки, История…).

---

## 15. Экран продажи (Seller) — UI-требования

Самый важный экран продукта.

При открытии продавец сразу видит:

- строку поиска (фокус / крупная);
- категории (горизонтальный скролл);
- список популярных / недавних товаров;
- доступ к корзине (bottom bar или tab).

После выбора товара: количество / объём → в корзину **без смены «приложения»** — один непрерывный flow.

Кнопка «Продать» — крупная, фирменный красный, всегда доступна при непустой корзине.

Себестоимость на экране **не отображается**.

---

## 16. Уведомления (визуальные типы)

| Тип | Индикатор | Пример |
|-----|-----------|--------|
| Критический остаток | 🔴 danger | Осталось 3 мл |
| Запрос скидки / возврата | 🟡 warning | Ожидает подтверждения |
| Успех | 🟢 success | Возврат подтверждён |
| Инфо / поставка | 🔵 info | Новая поставка |

Компоненты: `NotificationItem`, `Badge`, toast / banner.

---

## 17. Аналитика (Owner UI)

Состав экрана сверху вниз:

1. Фильтры периода и магазина  
2. **KPI-карточки** (самые важные цифры всегда сверху)  
3. Блок расходов (красные строки со знаком «−»)  
4. Итог «Чистая прибыль» (зелёный)  
5. Графики / диаграммы  
6. ТОП-таблицы  

Правило: пользователь **никогда** не ищет главные показатели глубоко в таблицах.

---

## 18. Доступность

- Крупные кнопки на телефоне (min 44×44px).
- Контраст текста ≥ WCAG AA где возможно.
- Понятные подписи (не только иконки).
- Подтверждение опасных действий.
- Нет скрытых критичных функций.
- Focus visible для клавиатуры (Owner).

---

## 19. Система компонентов

Все элементы — переиспользуемые компоненты в `src/components/ui/`:

| Компонент | Назначение |
|-----------|------------|
| `Button` | primary / secondary / soft / danger / ghost |
| `Input` / `Search` / `Select` | Формы |
| `Table` | Owner data grids |
| `Card` | Контейнеры данных |
| `Modal` / `Drawer` | Диалоги, подтверждения, mobile sheets |
| `Notification` / `Badge` / `Toast` | Статусы |
| `Tabs` | Карточка товара, карточка магазина |
| `Pagination` | Списки |
| `Tooltip` | Подсказки desktop |
| `Avatar` | Профиль |
| `PageHeader` | Заголовок страницы Owner |
| `EmptyState` | Пустые списки |
| `BottomNav` | Seller |
| `Sidebar` | Owner |

Новый экран = сборка из компонентов, а не новый CSS «с нуля».

---

## 20. Состояния интерфейса

Каждый список / экран поддерживает:

- **Loading** (skeleton, не «пустой белый экран»);
- **Empty** (текст + CTA);
- **Error** (понятное сообщение + повтор);
- **Success** (toast / зелёный индикатор).

---

## 21. Модальные окна и подтверждения

Обязательное подтверждение для:

- удаления / архивации;
- списания;
- подтверждения возврата;
- сброса пароля сотрудника;
- массовых операций.

Modal: заголовок, текст риска, Secondary «Отмена», Danger/Primary подтверждение.

## 22. Карточка магазина и товара (UI)

### Товар — Tabs

Основное · Цены · Остатки · Партии · История  

(Цены/себестоимость скрыты от Seller — Seller не открывает эту карточку в полном виде.)

### Магазин — Tabs

Обзор · Остатки · Сотрудники · История продаж · Возвраты · Скидки · Поступления · Перемещения · Ревизии · Действия сотрудников  

---

## 23. Брендинг и white-label

Согласно Vision §21, настраиваются:

- логотип;
- название;
- `--brand` / `--brand-hover` (и производные soft/ring).

Ядро компонентов не меняется — меняются токены компании.

---

## 24. Запреты (anti-patterns)

Не делать:

- фиолетовые «AI-градиенты» и glow ради красоты;
- разные радиусы на соседних экранах;
- emoji как постоянные иконки в Owner Console;
- показывать себестоимость продавцу «для удобства»;
- перегружать Seller dashboard аналитикой;
- делать продажу через 5+ экранов.

---

## Итог

UI Design System — это **контракт** между дизайном и кодом.

Две поверхности:

1. **Owner Console** — desktop sidebar, таблицы, аналитика, полный контроль.  
2. **Seller POS** — smartphone, bottom nav, крупные CTA, продажа за несколько касаний, без финансов.

Общий бренд (красный ARAMAT PLUS), общие компоненты, разные сценарии плотности и навигации.

Реализация в коде: `src/app/globals.css` (токены) + `src/components/ui/*` + `OwnerShell` / Seller layout.

**Следующий документ по цепочке:** User Flow Specification (сценарии переходов) или UI-макеты ключевых экранов на базе этой системы.
