## 1. Главная цель разработки

Разработка ведётся сразу как **конечный коммерческий продукт**, без временных решений и последующего переписывания.

Принципы:

- промышленная архитектура с первого дня;
- не создавать «MVP на HTML/CSS» с последующей переделкой;
- сразу финальный стек;
- каждый новый модуль готов к реальной работе;
- платформа на `Company` / theme — ядро переиспользуется для других клиентов.

## 3. Правильный порядок разработки (актуально)

```
1. Desktop UI Architecture (Owner)     ✅ TASK 01
2. Warehouse (ядро)                    ✅ TASK 02
3. Seller POS (мобильный) — ТЗ         📋 TASK 03 (live sale после Магазинов)
4. Stores / Магазины (Owner Desktop)   🔄 TASK 04  ← текущий
5. Live POS + Transfers/Returns depth
6. Inventory · Analytics · Notifications · Settings
7. Mobile Owner adaptation
```

> Desktop Owner ≠ увеличенный POS. POS — отдельное phone/tablet рабочее место.

```
Архитектура → База данных → Backend → Авторизация → API
    → Frontend модулей → Тестирование → Оптимизация → Запуск
```

Красивый интерфейс без схемы и прав = переделки. Так строятся коммерческие ERP.

## 12. Этап №8 — Партии товара

Инвариант (не нарушать):

```
Партия №1: 100 мл · cost 100 · дата прихода
Партия №2: 150 мл · cost 120 · дата прихода
→ НЕ объединяются
```

- себестоимость — на **Batch**;  
- цена продажи — на **Product** (+ PriceHistory);  
- смена sale price не меняет историю продаж и cost партий;  
- списание — **FIFO**.

См. `docs/batch-rules.md`.

## 17. Этап №13 — Скидки

```
Seller request → Owner notify → approve/reject → Seller → sale
```

Полный audit. Каталожная цена товара не меняется запросом скидки.

## 18. Этап №14 — Подарочные акции

При продаже backend сообщает, какой подарок выдать.

## 19. Этап №15 — Возвраты

Seller **не** оформляет возврат сам:

```
Запрос → Owner confirm → остатки · история · аналитика
```

## 20. Этап №16 — Ревизия

---

## 21. Этап №17 — Аналитика

Периоды: сегодня · неделя · месяц · год · произвольный.

По магазину и сети: выручка · себестоимость · расходы · скидки · чистая прибыль · топы.

## 22. Этап №18 — История

Отдельные журналы (не одна бесконечная таблица):

продажи · возвраты · пользователи · склад · цены · партии · скидки · ревизии · общий audit.

Поля: дата · время · пользователь · действие · объект · комментарий.

## 23. Этап №19 — Уведомления

- партия закончилась;  
- ревизия завершена.

## Итог

Такой порядок позволяет с первого дня строить полноценный коммерческий ERP: каждый модуль опирается на готовую архитектуру, без переписывания ядра. Платформа готова к другим клиентам: меняются бренд, настройки и оформление — ядро остаётся тем же.

**Сейчас главный риск — неверный UI.** Поэтому сначала идеальные поверхности (PWA + 3 shells), потом глубокая логика продаж.
