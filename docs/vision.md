# Vision Document №1

**Проект:** ARAMAT PLUS ERP  
**Подзаголовок:** Система управления сетью магазинов парфюмерии  
**Версия:** 1.0  
**Статус:** Утверждённый ориентир для всех последующих документов

> **Активная фаза:** [Product Vision Completion Phase](PRODUCT-VISION-LAYER.md) — критерий UI-сценария; порядок блоков 3.1 → Inbox → Perfume bottles → …

---

## 1. Описание проекта

ARAMAT PLUS ERP — современная облачная система управления сетью магазинов парфюмерии, предназначенная для полного контроля бизнеса в режиме реального времени.

Система объединяет владельца, центральный склад, магазины и сотрудников в единую онлайн-платформу.

Все данные хранятся централизованно и доступны в соответствии с правами пользователя.

Основная задача системы — заменить ручной учёт и обеспечить полный контроль над движением товаров, продажами, прибылью, остатками и работой сотрудников.

---

## 2. Цель проекта

Создать единую систему, которая позволит владельцу:

- контролировать весь бизнес с любого устройства;
- управлять центральным складом;
- управлять неограниченным количеством магазинов;
- отслеживать остатки товаров в режиме реального времени;
- анализировать продажи и прибыль;
- контролировать действия сотрудников;
- быстро принимать управленческие решения на основе аналитики.

---

## 3. Основные принципы проекта

При разработке системы соблюдаются следующие принципы:

- простота использования;
- высокая скорость работы;
- современный интерфейс;
- масштабируемость;
- безопасность данных;
- минимальное количество действий для выполнения операций;
- возможность дальнейшего расширения без изменения архитектуры;
- **универсальность платформы** (см. раздел 21).

---

## 4. Масштабируемость

Система не ограничивается пятью магазинами.

Архитектура должна поддерживать:

- один центральный склад (на компанию);
- неограниченное количество филиалов;
- неограниченное количество пользователей;
- неограниченное количество товаров;
- возможность открытия новых магазинов без изменения программного кода.

---

## 5. Структура сети

Пример структуры:

```
ARAMAT PLUS
├── Центральный склад
├── Магазин Душанбе №1
├── Магазин Душанбе №2
├── Магазин Худжанд
├── Магазин Бохтар
├── Магазин Куляб
└── ...
```

Количество магазинов определяется только потребностями бизнеса.

---

## 6. Основная концепция

**Центральный склад является главным источником данных.**

Именно на складе:

- создаются товары;
- изменяются цены;
- изменяется себестоимость;
- изменяются характеристики товара;
- принимаются новые поставки.

После передачи товара в магазин вся информация автоматически синхронизируется.

Склад является единственным источником актуальной информации о товарах (master data).

Партии товара хранятся **отдельно** (без объединения), себестоимость партии фиксируется при приходе; цена продажи может меняться владельцем без изменения истории уже совершённых продаж.

---

## 7. Типы пользователей

Система предусматривает следующие роли:

| Роль | Доступ |
|------|--------|
| **Владелец (Owner)** | Полный доступ ко всей системе |
| **Продавец (Seller)** | Только свой магазин (POS, запросы скидок/возвратов) |
| **Кладовщик (Warehouse)** | Только склад (товары, партии, перемещения) |
| **Менеджер (Manager)** | Права, назначенные владельцем |

> Примечание для разработки: роли и права должны быть конфигурируемыми; набор выше — стартовый для ARAMAT PLUS.

---

## 8. Типы товаров

Система должна поддерживать несколько типов товаров.

### Штучные товары

Примеры: часы, дезодоранты, освежители воздуха, заводские духи, косметика.

Учёт ведётся в штуках.

### Разливные духи

Учёт ведётся в миллилитрах.

Продажа возможна:

- фиксированным объёмом;
- произвольным объёмом.

После продажи остаток автоматически уменьшается.

---

## 9. Управление товарами

Каждый товар создаётся только один раз на центральном складе.

Все магазины получают информацию именно от склада.

Владелец может:

- изменить цену продажи;
- изменить себестоимость (через новые партии / корректировку политики);
- изменить характеристики;
- изменить категорию;
- изменить бренд;
- изменить минимальный остаток;
- изменить статус товара.

Все изменения master-данных автоматически применяются ко всей системе.

---

## 10. Поиск товаров

Каждый товар должен иметь несколько способов поиска.

Система поддерживает поиск:

- по названию;
- по бренду;
- по категории;
- по внутреннему ID;
- по артикулу;
- по штрих-коду.

Каждому товару автоматически присваиваются:

- внутренний ID;
- артикул;
- уникальный штрих-код.

Это позволяет быстро находить товар вручную или с помощью сканера.

---

## 11. Ценообразование

Для каждого товара хранится:

- себестоимость (на уровне партии);
- цена продажи (текущая, на уровне товара).

Владелец может изменить:

- только цену продажи;
- себестоимость новых партий;
- обе величины в рамках операции поставки / настройки.

После изменения новые продажи выполняются по актуальным значениям.

История уже совершённых продаж сохраняется без изменений (snapshot цены и себестоимости в строке продажи).

---

## 12. Работа продавца

Основная задача продавца — максимально быстро оформить продажу.

Весь процесс продажи должен занимать несколько действий:

1. найти товар;
2. указать количество;
3. оформить продажу.

Дополнительные операции (скидки, подарки, уведомления) должны выполняться системой автоматически.

---

## 13. Система скидок

Продавец не имеет права самостоятельно изменять цену.

Если покупатель просит скидку:

1. продавец формирует запрос;
2. система отправляет его владельцу;
3. владелец принимает решение;
4. после одобрения продавец завершает продажу по новой цене.

Каждая скидка сохраняется в истории.

---

## 14. Акции и подарки

Владелец может создавать акции.

Примеры:

- при покупке 100 мл — подарок;
- при покупке трёх товаров — подарок;
- при покупке на определённую сумму — подарок.

При выполнении условий система автоматически уведомляет продавца о необходимости выдать подарок.

---

## 15. Возвраты

Продавец не может самостоятельно оформить возврат.

Он создаёт запрос.

Возврат выполняется только после подтверждения владельцем.

После подтверждения:

- корректируются остатки;
- корректируется аналитика;
- создаётся запись в журнале операций.

---

## 16. Аналитика

Система должна предоставлять владельцу полную информацию о работе бизнеса.

Аналитика отображается:

- по каждому магазину;
- по всей сети;
- за день;
- за неделю;
- за месяц;
- за произвольный период.

Ключевые метрики: выручка, себестоимость, расходы, скидки, чистая прибыль, топ товаров, топ продавцов.

---

## 17. История операций

Любое действие пользователя сохраняется.

Примеры:

- создание товара;
- изменение цены;
- изменение себестоимости;
- продажа;
- возврат;
- передача товара;
- изменение пользователя;
- создание магазина.

Для каждой операции сохраняются:

- пользователь;
- дата;
- время;
- магазин (если применимо);
- описание действия.

---

## 18. Контроль остатков

Владелец может настроить минимальные остатки.

Примеры:

- разливные духи — менее 50 мл;
- часы — менее 5 шт.;
- дезодоранты — менее 10 шт.

При достижении минимального остатка система автоматически создаёт уведомление с указанием магазина, категории и точного наименования товара.

---

## 19. Дизайн системы

Интерфейс разрабатывается в фирменном стиле ARAMAT PLUS.

Основные принципы:

- светлый рабочий фон;
- фирменный красный цвет для основных действий;
- тёмно-серый текст;
- зелёный цвет для прибыли и успешных операций;
- красный цвет для расходов, списаний и предупреждений;
- минималистичный современный дизайн;
- одинаково удобная работа на компьютере и телефоне;
- тёмный sidebar + светлая рабочая область (Owner);
- Design System как единый источник UI-правил (см. `docs/design-system.md`).

Брендинг (название, логотип, цвета) должен быть **конфигурируемым** на уровне компании (см. раздел 21).

---

## 20. Главная цель проекта

Создать профессиональную ERP-систему, которая:

- полностью заменит ручной учёт;
- обеспечит полный контроль над сетью магазинов;
- позволит масштабировать бизнес без изменения архитектуры;
- сможет использоваться как универсальная платформа для других торговых сетей после смены фирменного оформления и настроек.

---

## 21. Универсальность платформы (ключ к масштабированию продукта)

Система должна быть **универсальной платформой**, а не одноразовой программой под одного клиента.

Конфигурируемыми должны быть:

- название компании;
- логотип;
- цвета интерфейса (бренд-токены);
- категории товаров;
- единицы измерения;
- роли и права пользователей;
- пороги остатков и уведомлений;
- валюта и параметры компании;
- бизнес-правила акций и скидок (в рамках ядра).

**Ядро системы** (склад, партии, магазины, перемещения, продажи, возвраты, аналитика, журнал) остаётся неизменным.

**Оболочка** (бренд, справочники, настройки) адаптируется под клиента.

Благодаря этому одну и ту же платформу можно использовать не только для ARAMAT PLUS, но и для других компаний **без переписывания кода**.

Технический задел: мультитенантность на уровне `Company` / `companyId` уже заложена в архитектуру данных.
