# ТЗ: Главная владельца v2 — панель управления бизнесом

**Проект:** AROMAT PLUS ERP  
**Версия:** 2.0 · 2026-07-30  
**Роль:** Senior Product Designer + UX + ERP Architect  
**Цель одной строкой:** владелец за 2–3 секунды понимает состояние бизнеса, а не список функций системы.

Связанные: [dashboard-owner](dashboard-owner.md) · [TZ-PREMIUM-OWNER-ERP](TZ-PREMIUM-OWNER-ERP.md)

---

## Принцип

> **Главная = панель управления бизнесом, не панель управления системой.**

Запрещено: показывать «сколько категорий», «сколько SKU» как главный смысл экрана.  
Обязательно: деньги, прибыль, проблемы, сеть, действие.

---

## Вопросы, на которые отвечает экран

1. Что происходит **сегодня**? (продажи, прибыль, чеки, средний чек)
2. **Где проблема?** (светофор 🟢🟡🔴)
3. **Что требует моего решения?** (скидки, возвраты, остатки, магазины без продаж)
4. **Как работает сеть?** (лучший / худший / без продаж)
5. **Что сделать сейчас?** (приём, отправка, отчёт, товар, склад)

## Структура экрана (4 зоны, сверху вниз)

### Зона 0 — Светофор (статус дня)

Одна строка под приветствием:

| Цвет | Условие | Пример |
|------|---------|--------|
| 🔴 | Есть срочные решения или товар = 0 | «3 запроса ждут решения» |
| 🟡 | Низкий остаток или магазин без продаж | «2 товара заканчиваются» |
| 🟢 | Всё в норме | «Сегодня всё под контролем» |

Клик → `/attention`.

---

### Зона 1 — «Сегодня»

Сетка 4 KPI (не три больших цветных блока):

| KPI | Подсказка (HelpTip) | Пустое состояние |
|-----|---------------------|------------------|
| Продажи | Сумма всех чеков за сегодня | «Продаж сегодня ещё не было» |
| Прибыль | После вычета себестоимости | «Прибыль появится после первой продажи» |
| Чеки | Количество продаж | «Данные обновятся после первого чека» |
| Средний чек | Средняя сумма покупки | «—» при 0 чеков |

Под KPI: мини-график продаж за 7 дней + Δ к вчера.

Цвет зоны: **зелёный** = деньги / рост.

---

### Зона 2 — «Требует внимания»

Единый список проблем. Каждая строка = **одна проблема + одно действие**.

| Тип | Действие |
|-----|----------|
| Запрос скидки/возврата | Одобрить / Отклонить (inline) + «Открыть» |
| Товар заканчивается | «Открыть товар» → `/warehouse/{id}` |
| Магазин без продаж | «Открыть магазин» → `/stores/{id}` |

Пустое состояние: 🟢 «Все процессы работают нормально».

Цвет: **оранжевый** = внимание, **красный** = срочно.

**Не дублировать** отдельным блоком «Рекомендации» и «Заканчивается» внизу страницы.

---

### Зона 3 — «Как работает сеть»

| Карточка | Данные |
|----------|--------|
| Лучший магазин | max(revenue сегодня) + сумма + прибыль |
| Худший магазин | min(revenue) среди активных |
| Без продаж сегодня | список магазинов с salesCount = 0 |

Пустое: «Все магазины продали сегодня» или «Магазинов нет».

Цвет: **синий** = информация о сети.

---

### Зона 4 — «Что сделать сейчас»

5 плиток (быстрые действия):

1. Принять товар → `/warehouse/receive`
2. Отправить → `/warehouse/transfers/new`
3. Отчёт → `/analytics`
4. Создать товар → `/warehouse/new`
5. Проверить склад → `/warehouse/stock`

Цвет кнопок: **бордовый** = главное действие (brand).

---

## Правила карточек

1. **Контекст:** каждая цифра имеет подпись или HelpTip (`?`).
2. **Не мёртвые нули:** `0` → объясняющий текст, не голая цифра.
3. **Δ:** где возможно — сравнение со вчера (`+15% к вчера`).
4. **Одна проблема = одно действие** — без «мертвых» ссылок.

## Цветовая система (не менять между экранами)

| Цвет | Смысл |
|------|--------|
| Бордовый (brand) | Главное действие |
| Зелёный (zone-money) | Деньги, рост, успех |
| Оранжевый (zone-alert) | Внимание |
| Красный (danger) | Опасность, срочно |
| Синий (zone-stores) | Информация о сети |
| Фиолетовый (brand/analytics) | Аналитика |

## Язык (абсолютное правило)

- Только **RU** или **TJ** — один экран = один язык.
- Все строки через `t("dashboard.*")` / `hints.*`.
- Enum из БД (`OWNER`, `SALE_CREATE`) → `labels.ts`, никогда в UI.
- Сервер отдаёт `titleKey`, не готовый текст.
