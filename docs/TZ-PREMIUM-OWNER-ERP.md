## Фаза A — «Владелец видит бизнес + продавец продаёт мл» (сейчас)

**Приоритет 1. Дашборд**

- Блок продаж сегодня: сумма, чеки, средний чек, Δ вчера, Δ неделя.
- Блок прибыли: выручка / себестоимость / прибыль (из уже существующих метрик sale).
- Склад: единиц, SKU/категории, «заканчивается N» → клик `/warehouse`.
- Магазины: сегодня продажи + прибыль + лучший товар (если есть данные).
- «Требуют внимания»: out of stock / low ml / магазин без продаж N дней.

**Приоритет 2. Парфюм = мл**

- В UI везде: `WEIGHT` → подпись «мл» / «Разлив», не «г» и не «граммы».
- Enum в БД **не переименовывать** в `MILLILITER` в этой фазе (ломка миграций); маппинг только в UI/API labels.
- POS: для `WEIGHT` — выбор объёма (5/10/15/30 мл + своё), шаг не ±1 «штука».
- Каталог POS отдаёт `accountingType`.

**Definition of Done A**

- Owner dashboard показывает бизнес-KPI из брифа (не «кол-во единиц» как главный смысл).
- Seller может продать 15 мл разлива без путаницы «шт».
- Нет регресса FIFO sale/transfer.

## Фаза B — Склад + аналитика денег

- Списание / ревизия / возвраты: убрать stub или явный «не подключено».
- Аналитика «Сеть»: итоги + лучший/худший магазин.
- «По магазинам»: таблица продажи / расходы / прибыль / клиенты.
- Вкладка «Расходы»: суммы по категориям за месяц, не только ссылки.
